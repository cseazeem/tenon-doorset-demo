For doorset teams

Less re-keying, fewer surprises on the factory floor.

What a technical team would notice day to day.

Specifications checked before pricingMissing closers, conflicting sizes, TBC hardware and vague fire-rating wording are flagged with the exact source line.
One hardware schedule drives everythingDoor-by-door hardware feeds the quotation, the BOM and purchasing, so a change is entered once.
No building from old drawingsSuperseded revisions are stamped and kept, and production waits for the current revision to be approved.
Traceable fire tag recordsTag, rating, batch, location and documents per doorset, with gaps highlighted and flagged for follow-up.
Release only when readyReview, hardware, drawings, BOM and materials are checked before a package reaches the floor.
Ask the project a question"What hardware is missing?" or "Which drawings have new revisions?" Answers come from the live records and show which ones were used.

The AI assists and a person decides. Every finding shows its evidence and confidence, approvals are recorded, and the system never certifies a doorset or verifies regulatory compliance. This demo runs the AI in rule-based mode; OpenAI, Anthropic or Gemini can be switched on with one setting.

What's built

A working application, shown honestly.

Built and working

  • Every screen here is the real application, running on a PostgreSQL database
  • Quotation, BOM and purchasing figures calculated by the server
  • Approvals by role, with names and times recorded
  • Drawing revisions protected against overwrite by the database itself
  • The demo project resets on its own without touching other data
  • 70 automated backend tests

Demo boundaries

  • The project, companies and data are fictional
  • AI runs in rule-based mode here; live AI providers are a setting
  • The fire tag register is a documentation aid, not a certification system
  • Not yet hardened for production (e.g. single sign-on, backups, monitoring)
